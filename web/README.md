# pyRadPlan web frontend (prototype)

A browser GUI for pyRadPlan that mimics the PySide6 main window and runs pyRadPlan itself in the
browser via [Pyodide](https://pyodide.org) in a web worker. The UI talks to the Qt-free application
layer `pyRadPlan.app` through the protocol in [PROTOCOL.md](PROTOCOL.md). **Not for clinical use.**

## Setup

Requires Node ≥ 20 (developed with Node 24) and npm.

```sh
cd web
npm install
```

Node 24 must be on `PATH`. The scripts that type-check, test, build or serve the mock backend first
run `npm run fixtures`, which records the mock's catalogues from `pyRadPlan.app` (see below): that
needs a Python with pyRadPlan's dependencies (`pip install -e .` in the repository root). `python`
(`python3` on Linux and macOS) is used unless the `PYTHON` environment variable names another
interpreter.

## Run

```sh
npm run dev            # http://localhost:5173/  (COOP/COEP headers set)
```

- `http://localhost:5173/?backend=mock` — mock backend (synthetic phantoms, fake dose, simulated
  progress), no Python at run time; a red banner says so. `&speed=0` makes computations instant, `&speed=3`
  slower. Only the dev server (and a build made with `VITE_ENABLE_MOCK=1`) has it: a production build
  contains no mock code and ignores `?backend=mock`. Its catalogues (engines, forms, tissue schema,
  objectives, ...) are recordings of `pyRadPlan.app` in `src/api/mock/fixtures/`. They are generated, not committed
  (git-ignored): `npm run fixtures` writes them from the pyRadPlan source of this checkout, and
  npm pre-hooks run it before `dev`, `build`, `typecheck`, `test` and the `e2e*` scripts.
- `http://localhost:5173/` or `?backend=pyodide` — the real backend: Pyodide + pyRadPlan in a worker.
  Needs the wheels and `manifest.json` in `public/pyrp/` (built by `web/pyodide/build.py`) and network
  access to the Pyodide CDN for numpy/scipy. The first start downloads ~40 MB.

Other URL parameters: `pyodide=cdn|<url>` (Pyodide runtime location), `packages=<url>` (package wheel
mirror), `pyrp=<url>` (pyRadPlan wheel directory), `sliceMode` (force the renderer's per-slice texture
fallback). Outside the dev server, `pyodide`, `packages` and `pyrp` are honoured only for URLs below the
app's own directory (`BASE_URL`; and `pyodide=cdn`), so a crafted link cannot load code from elsewhere,
not even from another site on the same origin. `VITE_BACKEND=mock` changes the default backend of a
build that includes the mock (see above).

```sh
npm run build          # type check + production build into dist/ (includes dist/pyodide-runtime/)
npm run preview        # serve dist/ with the same headers on http://localhost:4173/
```

The build also writes `dist/THIRD_PARTY_NOTICES.txt` (generated by `scripts/thirdPartyNotices.ts`
from the npm packages actually in the bundle plus the Pyodide runtime, CPython, Emscripten and,
with `PYRADPLAN_COI=1`, coi-serviceworker; license files are copied verbatim, `licenses/<name>.txt`
is the fallback for packages without one, and the build fails if neither exists) and
`dist/LICENSE.txt` (pyRadPlan's own). Help > Third-party Licenses links both and lists the Python
packages from inside the backend.

## Disclaimer and privacy notice

On the first visit a modal shows the research-use disclaimer (the texts of
`../pyRadPlan/app/about.json`, shared with the Qt About dialog) and the privacy facts; the backend
only starts after "I understand, continue". The acknowledgement is one `localStorage` entry
(`pyradplan.notice-acknowledged.<hash of the texts>`), so changed texts ask again. The notice stays
reachable from the status bar and Help > About. The e2e scripts acknowledge it once per browser
context through `e2e/notice.mjs`; `e2e:menus` checks the fresh-profile behaviour.

## Publishing (GitHub Pages)

Two channels, `/latest/` (newest release) and `/develop/` (develop branch), assembled into one site
by [`.github/workflows/web-pages.yml`](../.github/workflows/web-pages.yml) with
`scripts/assemble_pages.mjs`; a release without `web/` gets a placeholder page. The build shows its
channel, version and commit in Help > About (`VITE_PYRADPLAN_CHANNEL`, `VITE_PYRADPLAN_VERSION`,
`VITE_PYRADPLAN_COMMIT`). Decision record, the local test recipe and the one-time admin steps
(Pages source "GitHub Actions", environment rules, variable `WEB_PAGES_ENABLED`):
[`docs/development/web_publishing.md`](../docs/development/web_publishing.md).

```sh
npm run pages:test -- --skip-wheels   # newest release tag as latest, this checkout as develop, into ../_site; serve + smoke test
```

The same script runs in the `build` job of that workflow (every pull request touching the web
paths, manual runs from any branch; the site is the downloadable artifact `web-pages-site`) and in
the GitLab job `web-pages` (artifact `_site/`, one week). Only the `deploy` job publishes, for
develop and releases, once the variable `WEB_PAGES_ENABLED` is `true`.

## Tests

```sh
npm test               # vitest: codec, mock backend, renderer math (geometry, LUTs, marching squares)
npx tsc --noEmit       # type check
npm run e2e            # Playwright (Edge, SwiftShader WebGL) against ?backend=mock; screenshots in e2e/screenshots/ (git-ignored)
npm run e2e:viewer     # viewer parity (beams, drag, snapshots, VOIs, analysis window) against the mock, port 5202
npm run e2e:plan       # plan widget, config forms, tissue dialog, objectives, status window against the mock
npm run e2e:menus      # menus, dialogs, saves (downloads), loads, base data, settings, help, log, dark mode (port 5203, screenshots menus-*.png)
npm run e2e:pyodide    # the whole GUI against the real Pyodide backend (~3 min, see below); `-- --preview` uses the production build
```

`e2e:pyodide` clicks through TG119 with the web profile defaults in stages (boot, phantom from
File > Open Example Phantom, Calc. Dose Influence + Optimize of the default plan, plan form +
engine / scenario / optimization dialogs, objectives, 5 beams with the status window, viewer,
snapshot + analysis window, VOI edit, every File-menu save the capabilities report available
(downloads kept in `e2e/downloads/`), reload of the workspace pickle and the plan `.mat`, Load Dij,
base data add/remove, Preferences, licenses, About, log level, dark mode, educational mode, a robust
1-beam plan (worst-case grid, robust objective) with its scenarios in the viewer and the analysis
window, a proton plan with its bio models and the tissue dialog, Stop during the dose calculation). Each stage screenshots `pyodide-*.png`; a failing stage is recorded
(`pyodide-fail-<stage>.png`) and the run continues; `--only=<stage,...>` runs a subset. Timings
and memory go to `e2e/screenshots/pyodide-metrics.json`. It needs the wheels in `public/pyrp/`
(`npm run build -- --skip-pure` in `web/pyodide`) and network access to the Pyodide CDN.

The backend calls themselves are covered without a browser by `npm run app-smoke -- --strict` in
`web/pyodide` (rebuilds the wheels, then runs `app_smoke.table.js` under Pyodide in Node; needs
`PYTHON=<python with the build deps>`).

The e2e scripts use the installed Microsoft Edge (`channel: "msedge"`); `npm run e2e -- --chromium`
uses Playwright's own Chromium instead (`npx playwright install chromium` first), `-- --headed` shows
the browser.

## CI

The GitHub workflow [`.github/workflows/web.yml`](../.github/workflows/web.yml) (push to
`main`/`develop`/`rc/**`/`devops/**`, pull requests, manual dispatch; only when `web/`, `pyRadPlan/`,
`pyproject.toml` or the workflow change) and the `web-*` jobs of `.gitlab-ci.yml` (internal branches,
same file filter) run three jobs, all on Linux with Node 24:

| Job | What it runs | Time |
|---|---|---|
| frontend | `npm ci`, `npm run typecheck`, `npm test`, `npm run build`, the four mock-backend e2e scripts | ~8 min |
| pyodide | in `web/pyodide`: `npm run build`, `npm run pipeline -- --mode photons --preset fast` (plus a plausibility check of the target D95), `npm run app-smoke -- --strict`, `npm run test:shim` (Python 3.13 with `pip install -e .` and pytest) | ~10 min |
| pyodide-e2e | wheels from `npm run build`, then `npm run e2e:pyodide` (the full click-through against the real backend) | ~12 min |

The browser is Microsoft Edge installed with `npx playwright install --with-deps msedge`, because
the scripts launch `channel: "msedge"`; WebGL runs on SwiftShader as locally. The Pyodide packages
come from the jsDelivr CDN. GitHub caches the npm downloads and `web/pyodide/.cache/packages`. A
failed run uploads the e2e screenshots (`pyodide-fail-<stage>.png` for the real backend) as an
artifact. To reproduce a job locally, run the same commands in the same order.

## Layout

```
web/
  PROTOCOL.md              UI <-> pyRadPlan.app protocol (shared contract)
  index.html, vite.config.ts, tsconfig.json, package.json
  src/
    main.tsx, App.tsx      entry, main window layout (menu, three columns, status bar, dialogs)
    styles.css             Qt-like look (group boxes, dense controls)
    assets/                logos copied from pyRadPlan/gui/assets/logos
    api/                   typed protocol client
      protocol.ts          message / method types (incl. PROTOCOL.md amendments)
      codec.ts             {$array} <-> typed arrays
      backend.ts           Backend interface, BaseBackend, BackendError
      mock/                MockBackend + synthetic phantoms / fake dose
      pyodide/             PyodideBackend, module worker, glue.py (runs inside Pyodide)
    store/appStore.ts      zustand store: session state, volumes, logs, viewer settings, actions
    renderer/              framework-free slice renderer (WebGL2 + Canvas2D overlay)
    components/            React widgets mirroring the Qt widgets
  test/                    vitest unit tests
  e2e/                     Playwright scripts + screenshots
  docs/renderer.md         renderer options, decision, verified limits
  docs/frontend.md         architecture, worker, Pyodide loading, protocol interpretations
  scripts/gen_colormaps.py regenerates src/renderer/colormapData.ts from matplotlib
  scripts/gen_mock_fixtures.py  records src/api/mock/fixtures/*.json from pyRadPlan.app
  scripts/mock_fixtures.mjs     runs it (`npm run fixtures`, before the scripts that need the files)
  scripts/thirdPartyNotices.ts  Vite plugin writing THIRD_PARTY_NOTICES.txt and LICENSE.txt
  scripts/assemble_pages.mjs    builds and assembles the GitHub Pages channels
  licenses/                fallback license texts (Pyodide, CPython, Emscripten, coi-serviceworker)
  pages/coi-serviceworker.js  cross-origin isolation for hosts without headers (PYRADPLAN_COI=1)
  pyodide/                 (porting agent) bootstrap.js, wheel build, headless harness
  public/pyrp/             (generated) pyRadPlan wheel, SimpleITK shim, pure wheels, manifest.json
```

## Viewer controls

Wheel: next/previous slice · Ctrl+wheel: zoom at cursor · left/middle drag: pan · right drag: zoom ·
double-click: reset view · ↑/↓, PgUp/PgDn: slices (canvas focused) · hover: position, HU and dose.
